# Development roadmap — native Android

Historical master directive retains all product and quality requirements; React Native replaces Flutter-specific implementation instructions.

1. Verify existing environment, initialize official RN TypeScript template, install local dependencies, request missing Android SDK approval, then verify baseline tests/typecheck and default debug APK.
2. Implement Soft Harmony semantic tokens, accessible reusable controls, original brand/splash, typed English/Turkish catalogs, navigation and persisted settings/onboarding.
3. SQLite schema/migrations/repositories with transaction/FK/restore tests; Tasks, Today Compass, Focus Three, Gentle Reset and recurrence.
4. Goals/milestones, habits/history/streaks with calendar-based tests and real persistence.
5. Notes autosave, calendar, lifecycle-safe focus sessions; real insights and global search.
6. Native local notifications with permission/reboot reconciliation; transactional versioned backup/import preview.
7. Dark theme, large-text/TalkBack/reduced-motion/responsive refinement, meaningful unit/widget/integration tests and Android builds.
8. Approved device QA, native 16 KB validation, privacy/Data Safety preparation and deliberate AAB signing/release plan.

Each phase requires implementation evidence; no phase accepted solely because source files exist. Missing SDK approval blocks baseline native build; does not justify false success claims.
